## Shared pattern

**Choose → explore recursively → undo.** The mutable `path` represents the current partial answer; save a **copy** (`[...path]`) when a complete answer is reached.

## Differences

| Problem | Recursion state | When to record | Avoid duplicates |
| --- | --- | --- | --- |
| 78 Subsets | `start`, `path` | At every call | Advance `i` from `start` |
| 77 Combinations | `start`, `path` | When `path.length === k` | Advance `i` from `start` |
| 46 Permutations | `used[]`, `path` | When `path.length === n` | Track each chosen index |

```js
function subsets(nums) {
  const result = [], path = [];
  function dfs(start) {
    result.push([...path]);
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      dfs(i + 1);
      path.pop();
    }
  }
  dfs(0);
  return result;
}
```

## Complexity

Subsets O(n×2ⁿ) output construction; combinations O(k×C(n,k)) output construction; permutations O(n×n!) output construction. Auxiliary recursion/path O(n), excluding output.

## Past mistakes and feedback

- **Recovered cheat-sheet issue:** Forgetting to copy `path` means every stored result can reference the same mutable array.
- **Observed study focus:** Distinguishing `start` (no reuse earlier indices) from `used[]` (choose any unused index for each position).
- **Common trap:** Recording only leaves for subsets misses intermediate subsets including `[]`.
