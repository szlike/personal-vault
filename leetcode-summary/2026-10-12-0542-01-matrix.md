# 542. 01 Matrix

**Recorded:** 2026-10-12

## Problem

Given a grid of 0s and 1s, return a grid where each cell holds the distance to the nearest 0. LeetCode problem 542.

## Pattern

Multi-source breadth-first search (BFS). Seed the queue with every 0 cell at distance 0, then expand level by level. The first time a cell is reached, that distance is the shortest, because breadth-first search explores in increasing distance order.

Depth-first search (DFS) cannot find shortest paths here. That is a limitation of the tool, not a bug in the code. Depth-first search goes deep first, so the first path it finds to a cell is not necessarily the shortest one.

## Complexity

- Time: each cell is processed once, so the time grows with the number of cells in the grid.
- Extra space: the queue and the result grid both grow with the number of cells in the grid.

## Key insight

Seed from all the 0s at once instead of searching from each 1. Multi-source breadth-first search turns a shortest-distance question into a level-by-level expansion, and the seeding is what makes the `-1` guard work as the "is this a 1?" test.

## Past mistakes & points to improve

- October 11 to 12: `Array(lenY).fill(Array(lenX))` shared one inner array across all rows, the third appearance of this bug. Fix: use `Array.from({length: m}, () => new Array(n).fill(0))`, which builds a fresh array for every row.
- October 11 to 12: the queue head never advanced, causing an infinite loop. Fix: the head must move forward every time a cell is taken from the queue.
- October 11 to 12: `Infinity` and `-1` used as visited markers. Fix: a visited marker must collide with nothing the code still needs to distinguish.
- October 11 to 12: `JSON.parse(mat.toString())` throws, because `toString` flattens the grid instead of producing valid JSON. Fix: do not parse a flattened string as JSON. Copy a grid cell by cell or with a fresh-array construction.
- October 11 to 12: the head advanced twice per cell, once in `queue[head++]` and once in a separate `head++`. Fix: advance the head exactly once per cell processed.
- Standing rule from this problem: Big-O notation tells you whether a solution scales, but constant factors tell you whether it ships. The dynamic programming version and the breadth-first search version share the same Big-O time complexity, yet the dynamic programming version ran about 50 percent faster because of fewer allocations and fewer cache misses.
